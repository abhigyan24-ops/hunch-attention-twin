# Stage 8L decisions

The prompt expressly permits one root script check:s8l despite the general Task1A root-package restriction; only that key is in scope. Frozen contracts remain unchanged.

Receiver adjusted timestamps are stored as local metadata beside the canonical event, never extra core event fields. Durable batch settlement must include valid events and metadata-only tombstones before ACK. Existing own-event JSONL remains the laptop sender's source of truth. Pairing/session credentials require encrypted safeStorage; no plaintext fallback. No auto-confirm option is exposed in the real app; tests inject a synthetic confirmation callback.

CCR-8L-1 resolved by owner on 2026-10-29: approved flowing->working, browsing/gaming->distracted, away->break, and suppression of stuck/idle_open/offline state snapshots. The main app now explicitly enables this partial mapping. Change-triggered state and5second heartbeats use the same mapping; silent/stale/future observations are suppressed. Ping, event and command sync stay independent. No frozen schema change or fabricated focus token. Fine-grained mappings for the suppressed states remain future contract work, not a blocker to this approved behavior. Full ContextSnapshot persistence still awaits the earlier snapshot-source request; no missing task/fatigue/phone fields are invented.

Receiver command kill_switch does not fabricate heldCount=0: the laptop has no notification actuator, and only subsequent phone state/held_list can update held items. Outbound pending commands expire visibly and are cleared on disconnect, never replayed. Per-pair namespace isolates dedup/command journals across fresh pairing keys; unpair removes encrypted PK+sid, while old canonical event history remains app-private.

CCR-8L-2 (proposed; no frozen edits): hello.schema.json requires proto contains1, so a strict relay rejects a no-common-version hello before endpoint negotiation can send unsupported_version. Current behavior rejects/counts it safely, but precise update-app UX cannot be demonstrated through that strict relay. Smallest reviewed contract follow-up would permit a syntactically valid nonempty version list through outer hello validation and let authenticated endpoint negotiation decide; vectors/protocol acceptance tests would need owner review.

Shared-tool gaps (read-only): tools/verify-sync.mjs compares common event IDs without proving coverage; laptop/scripts/verify-sync-coverage.mjs adds that check. tools/privacy-scan.mjs CLI prints matching excerpts, so laptop/scripts/privacy-check.mjs calls its exported scanner and prints counts only. MockPeer CLI flags described by the guide are not implemented; automated tests invoke the exported MockPeer API, not a fictitious live-device CLI. Real-device attack-harness work remains an explicit integration request.
